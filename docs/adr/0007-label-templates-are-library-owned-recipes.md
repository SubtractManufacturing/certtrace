# Label Templates are library-owned recipes

A Label is a physical sticker or sheet on a Material. How it looks is not a single global hard-coded PDF: each Library owns a list of Label Templates (paper size + an ordered list of content items — which Material information and optional QR/barcode appear, each with horizontal align and Small/Medium/Large relative size), with exactly one default. CertTrace auto-lays out content for the size using those per-item hints; codes encode the Material id for now. New libraries (and upgrades from the old `labelTemplate: "standard-qr"` string) get two starters — `4×6 in` (default) and `8.5×11 in` — rather than preserving the legacy 4×2 layout. Rejected: one opaque template id with no size/content model; freeform drag-and-drop label *design* (2D placement on the page); richer QR payloads before CertTrace can act on them; silent one-click print without a preview. Reordering the content stack in the template editor (including drag handles) is in scope — that is stack order, not freeform design.
